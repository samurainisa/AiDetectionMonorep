# Краткое пояснение к диаграмме

## Основные компоненты

- **Пользователь / преподаватель** работает с системой через браузер.
- **Frontend** реализован на Vue.js и отвечает за загрузку текста/файла, отображение результата, подозрительных фрагментов и истории.
- **Backend** в проекте фактически реализован на Flask, а не на Django. Он принимает запросы от frontend, обрабатывает файлы, запускает анализ и сохраняет результаты.
- **База данных** PostgreSQL хранит историю проверок, результаты анализа, пользователей и данные антиплагиата.
- **BERT / RuBERT-модель** вынесена в отдельный ML-сервис и используется для локальной проверки текста на признаки ИИ.
- **Pangram API** используется как внешний сервис проверки, если выбран облачный режим анализа.
- **Модуль антиплагиата** встроен в backend и сравнивает текст с сохраненным корпусом документов.

## Основной поток работы

1. Пользователь загружает текст или документ через веб-интерфейс.
2. Backend принимает запрос.
3. Если загружен файл, backend временно сохраняет его в папку с файлами и извлекает текст.
4. Текст передается в модуль анализа.
5. Модуль анализа обращается к BERT/RuBERT-модели или Pangram API.
6. Дополнительно запускается внутренняя проверка на совпадения.
7. Backend сохраняет результат и историю проверки в PostgreSQL.
8. Frontend показывает пользователю результат, подозрительные фрагменты и историю анализов.

## Важные уточнения

- В задании упоминался Django, но в коде найден Flask. Поэтому на диаграмме указан Flask как фактическая серверная технология.
- Файловое хранилище показано упрощенно как папка с файлами. По коду файл нужен временно: после извлечения текста он удаляется.
- Caddy, Docker volume, dev-режим и внутренние endpoint-адреса убраны из диаграммы, потому что для слайда защиты они перегружают схему.
- Внешний антиплагиат в коде не найден. Антиплагиат реализован внутри backend.
